# Revision-240 CS1 continuation — 2026-10-29

Historical scoped implementation evidence, continuing the [TSPS adoption batch](TSPS-ADOPTION-2026-10-29.md).
The [roadmap](PORTING-ROADMAP.md), [matrix](../reference/rs240-port/PORT-MATRIX.md)

## Implemented subset

- `cache::osrs240::cs1` interprets the exact-240 `classEL.method3945` arithmetic
  stream through typed fact queries. Java int overflow, stream-order operators,
  truncating division, MIN/-1, ignored zero divisors, masked shifts, missing -2
  and failed -1 results are explicit. Diagnostics distinguish failures from valid
  negative values. The source's zero-valued operand behavior for unknown CS1 words
  is preserved; CS2 unsupported instructions remain errors.
- `classGP.method5615` comparisons and `method5609` %1–%5 substitution select
  disposable presentation in the shared application/game-ui pipeline. Native now
  calls that pipeline. The presentation callback can modify only a cloned body,
  leaving layout, picking topology and GameState authority intact. Empty alternate
  text retains live primary text; alternate sprite absence stays absent. Shared
  live font, spacing, alpha, angles and other fields are preserved. Asset requests
  cover both authored sprite/font choices and retained secondary sprites.
- The revision adapter owns the `classKJ` experience table. CS1, CS2 STAT_BASE and
  plugin real-level projection share its level-99 cap. This fixes the former CS2
  helper's virtual-level result above 99. CS1 totals the 24 enabled 240 skills;
  it does not borrow the older 23-skill plugin ABI enumeration. Raw CS1 run energy
  remains distinct from CS2 visible percent. World coordinates read committed
  fine position plus the one-tile player's centre, rather than the queued endpoint
  or renderer motion.
- Seven location definitions rejected by the earlier audit actually contain
  authored scale [1,1,0]. Exact-240 ObjectComposition/ModelData accept zero scale
  factors. The decoder now preserves them; the existing integer transform already
  collapses that axis correctly. Footprint bounds remain separate. No replacement
  scale, decoration offset or depth correction was added.
- `interface_probe --cs1` exercises selected actual-cache interfaces with the
  shared presentation and real CPU assets, recording node/quad counts, expression
  and asset diagnostics, and unchanged semantic fingerprints. It does not execute
  CS2 scripts or establish visual parity.

## Ownership and limits

There is no new authoritative state or fingerprint format. Expression results are
cached only within one widget projection; the next projection rereads committed
facts. Budgets bound expression words, text expansion and diagnostics. Native logs
through its existing bounded diagnostic owner. Cache/revision decoding and formulas
stay in adapters, while application supplies live facts and game-ui paints.

Legacy widget inventory arrays are not retained/bound yet. Their queries return a
compatibility failure with an explicit diagnostic; modern inventory IDs are never
inferred from widget numbers. Missing skills/varbits similarly remain visible
rather than becoming neutral success. A failure sentinel can still satisfy a
source comparison, as in the original client.

Still open: hover colors/tooltip activation, legacy buttons and complete CS1
inventory bindings, sprite/layout/clipping nuances, model painting/playback,
secondary-sprite clearing (the existing runtime field cannot distinguish an
unwritten value from a cleared value), transformed-player footprint semantics,
full initialization/lifecycle acceptance and live native/browser/reference-client
comparison. A selector being projected does not establish a rendered model.
