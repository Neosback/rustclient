# First-party plugin ports: source ledger

One section per ported `RuneLite` plugin. Each row maps a source file or behavior to its Rust owner and states
**implemented** and **verified** separately: *implemented* means code exists and is reachable in the native
client; *verified* names the test or measured comparison that backs it. "Unit" means an automated Rust test;
"live" means a comparison with the running reference client, which has not been run for any row below unless
stated. Settings come from `crates/plugin-host/src/first-party-schemas.json`, generated by
`tools/builtin-plugins/first_party_schemas.py` from the vendored `*Config.java` interfaces.

Platform context: plugins run on plugin API 0.2 (ADR-0006) in `crates/first-party-plugins`, one module each.
The settings sidebar lists each plugin with its own switch; the switch is the schema's `enabled` setting
(`PluginDescriptor.enabledByDefault`).

## roofremoval

Sources: `plugins/roofremoval/{RoofRemovalPlugin,RoofRemovalConfig,RoofRemovalConfigOverride}.java`,
`resources/.../roofremoval/overrides.jsonc` (copied verbatim to `crates/first-party-plugins/data/roofremoval/`).

| Source | Rust owner | Implemented | Verified |
| --- | --- | --- | --- |
| `removePosition`, `removeHovered`, `removeDestination`, `removeBetween` -> `Scene.setRoofRemovalMode` flags | `first-party-plugins::roofremoval` -> `SceneFlags::roofs` -> `scene::RoofView::hidden` | yes | unit: plugin mode flags, `roof_modes_hide_the_roofs_over_their_target_tiles` |
| Roof building (`Scene.buildRoofs`: roofs are connected regions of tiles flagged under-roof) | `scene::RoofVolumes` (8-neighbour flood fill per plane, slots 1..4095) | yes | unit: connectivity, exhaustion, per-plane numbering |
| Hiding one roof | per-vertex roof slot in `SceneVertex::texture_uv[3]`, hidden-slot bitmask in the world shader | yes | unit + shader validation (naga); no pixel capture |
| `overridePOH` (whole POH regions flagged) | plugin `areas()` -> `PluginOutput::roof_areas` | yes, but unreachable: the client does not load instanced scenes yet | unit: region math and switch |
| `overrides.jsonc` area flags | plugin `load_overrides()` -> `roof_areas` -> `SceneAsset::roofs_with` | yes | unit: 131 regions / 527 areas parse; area -> roofed tile -> tagged geometry |
| `TILE_FLAG_UNDER_ROOF` also feeds the client's own roof line-of-sight cut | `RoofVolumes::roofed` used by `RoofView::top_level` | yes | unit: override changes `top_level` |
| Scene reload when overrides change (`setGameState(LOADING)`) | `NativeApp::sync_roof_areas` -> scene reprojection | yes | not exercised against a live scene |
| `PreMapLoad` -> `performRoofRemoval` | areas follow `ClientSnapshot::scene_base/size` every update | yes (level-triggered instead of event-triggered) | unit |

Known differences and unverified assumptions:

- One override area in the source (`13871`, y bounds reversed) is a no-op in the Java loops; `areas()` drops it the
  same way.
- The vanilla line-of-sight cut (`top_level`) still runs under the plugin. Whether the injected client replaces it
  while a removal mode is set was not verified; with both active, standing under a roof hides everything above the
  player's plane, as in the unmodified client.
- `removeBetween` uses the client's camera-to-player tile walk at every pitch. The source describes "low camera
  angles"; the pitch threshold in the injected client was not found, so the walk is applied whenever the mode is on.
- Roof volumes follow the RustOSRS convention: geometry on plane `n + 1` belongs to the roof region of plane `n`.
  Actors carry no roof slot, so they are never hidden by a roof mode, only by the level cut.
- Hovered tile: the pointer's terrain pick ignores hidden roofs by design (pointing at a roof removes it).
- Roofs are 8-connected within one plane. RustOSRS additionally joins overhangs; that deviation is not ported.
