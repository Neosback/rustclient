## Changes and source differences

The game UI now rasterizes to an encoded-RGB logical canvas. Its GPU compositor implements nearest,
linear, Mitchell, Catmull-Rom, xBR and hybrid sampling. The source cubic kernel uses radial distance
and Catmull-Rom anti-ringing; it is not a separable bicubic filter. World and premultiplied UI combine
in encoded space before one display conversion. The shared source color correction applies to both;
shell chrome keeps its own retained texture and input transform. Canvas resources/bindings persist
until dimensions/world targets change. UI source coordinates and physical pointer conversion use the
same TitleViewport, including HiDPI/stretched offsets.

The supplied/vendored xBR fragment declares `f4` without initializing it, then reads it in its active
CORNER_C path. The WGSL port defines `f4 = h5.yzwx`, the corresponding rotated F4/B1/D0/H5 neighborhood.
This intentional correction removes undefined behavior; it prevents claiming bit parity with that
undefined GLSL result. The port computes neighborhoods in the fragment stage rather than spending
portable inter-stage slots on every source coordinate. Notices are retained in crates/renderer/NOTICE.

Texture filtering level 0 now disables mip selection. Anisotropic minification uses wgpu's required
linear filters; explicit shader level-zero loads preserve nearest magnification and cutout alpha.
U clamps, V repeats, scroll uses the committed cycle modulo 128. Classic capacity remains 256 layers
of 128px RGBA; source Java allocates its array from the texture-definition count. Malformed images,
texture IDs, geometry indices/priorities/spans and device-budget overruns fail before GPU submission.
HD needs a different capacity/memory policy, not larger unchecked allocations.

Native presentation now consumes the effective GPU frame cap. It shares the existing FPS-plugin
limiter, chooses the stricter cap and schedules a render deadline independently of 20ms game cycles.
Locked mode targets 50 FPS; unlocked/no-vsync honors fpsTarget; effective FIFO/adaptive presentation
uses platform pacing. Missed frames never create semantic catch-up frames. Hidden windows stop
presentation work. This does not implement floating animation vertices or subcycle actor animation.
Offline title-window cap measurements pass below; authenticated gameplay timing remains outstanding.

All 12 active supplied resources match the pinned Java resources byte-for-byte. The additional
historical compute/OpenCL files are not loaded by the pinned active plugin. Their face-priority
purpose is handled by the existing CPU ordering owner, with full acceptance still outstanding.
2008HD resources are separately inventoried and excluded from the approved classic plugin scope.
The region-list resource now drives normal-map scenery admission; see the 2026-10-27 continuation below.

## WebGPU and 117HD constraints

Adapter support and **granted device** capabilities are reported separately. The tested browser used
only core features/limits: 8192px textures, 256 array layers, 256MiB maximum buffer, 128MiB maximum
storage binding, 64KiB uniform binding, 4 bind groups and 16 sampled textures per stage. These are
negotiated device limits, not a statement of total VRAM. Higher supported limits must be requested
explicitly; allocations still require memory budgets. Baseline MSAA supports 1/4; a 2x request can
resolve to 4x in the browser and must say so. Native additional counts require enabled format features.
See [WebGPU limits](https://www.w3.org/TR/webgpu/#limits) and
[wgpu device requests](https://docs.rs/wgpu/30.0.1/wgpu/struct.DeviceDescriptor.html).

The stock rendering features fit WebGPU; GLSL/OpenCL must become reviewed WGSL/engine operations.
Keep f16, subgroups, timestamps, compression and native-only features optional. Browser presentation
controls vsync. Use bounded uploads, texture/material paging and storage chunking for large scenes;
do not assume a native driver's maximum limits are a portable allocation policy.

For scale, a full-mip 256-layer 128px RGBA array is about 21.3MiB; at 1024px it is about 1.33GiB
before normals, shadows or scene buffers. HD therefore needs explicit residency/quality budgets.
An HD pass graph can use linear HDR world/shadow/bloom targets, then tone-map into the existing
encoded world/UI composition boundary. Keep one scene and actor representation and typed plugin
render-policy services; external plugins do not receive GPU handles.

## Approved completion order — 2026-10-29

The machine-readable `completionOrder` in [gpu-audit.json](gpu-audit.json) records source anchors,
implementation owners, dependencies and acceptance for each group. It is the current ordering of
these existing gaps, not a new source inventory or completion percentage. None is closed by this
sidebar/lifecycle pass. Independent preparation can overlap; downstream acceptance waits for facts.

1. **Extended scenes.** Extend the authoritative loading owner, then share its bounds with scene
   admission, fog, culling, picking and residency. No second scene or cosmetic draw-distance override.
2. **Float poses.** Preserve source floating vertices and implement removeVertexSnapping in projection
   and upload. Committed actor positions/animation state remain unchanged. This can begin alongside 1.
3. **Upload scheduling.** After 1/2 establish payloads and invalidation, measure bounded scheduling and
   useful numThreads behavior. Include cancellation, generations, memory and browser policy.
4. **Metadata, world views and ordering.** After 1/2, retain tint, authored alpha-array presence, NPC
   customization and world-view/instance transforms; finish frustum and multi-zone ordering cases.
5. **Platform lifecycle.** Complete real FPS/vsync and reconstruction acceptance after scheduling and
   scene ownership settle. Native title-window/probe results and the new shared browser shell remain
   partial evidence; playable browser gameplay and real device-loss acceptance are open.
6. **Reference acceptance.** Close exact 240 comparisons and source-test dispositions only after the
   preceding dependencies. Preserve the existing xBR f4 correction as a documented source deviation.

`expandedMapLoadingChunks`, `removeVertexSnapping` and `numThreads` remain disabled/unimplemented.
Fog and vsync remain partial. Shared GPU preference interpretation, effective hardware-limit notes,
Always on presentation and lifecycle statuses do not implement those missing rendering semantics.
Source-test/resource inventories and successful shader compilation do not establish plugin parity.
117HD material paging, HDR/shadows/postprocess and budgets stay a separate later workstream. No Rust
software rasterizer or new external GPU callback ABI is introduced.
