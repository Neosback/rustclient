Checkpoint for a user-requested pull-forward of roadmap Phase 11 (classic rendering parity).
[SCENE-DEPTH-240](SCENE-DEPTH-240.md) is the earlier, historical record; its placement rules were
derived from the 235 deob and are superseded here for the rules listed below. Owner: `crates/scene`
(`locations.rs`, `decorations.rs`).

## Evidence

Stock 240 (`references/rl-suite-240/sources-semantic`, read-only):

- `classDI.method3340` (load-time addObjects): wall decoration branches for shapes 4-8, and the
  `Scene.method4502` call sites after shapes 0, 2 and 9. `classDI.method3336` is the server
  LOC_ADD path and never calls the rescale.
- `classDI.field1503/1505/1506/1507/1508` hold the orientation flags and the cardinal and diagonal
  unit steps. `Scene.method4495` creates the decoration, `Scene.method4502` rescales it.
- RuneLite 240 `SceneUploader` draws plate 2 with `getXOffset2/getYOffset2`.

`dd` is the `decorDisplacement` (opcode 28, default 16) of the base definition of the boundary already
on the tile. `C` and `D` are the cardinal and diagonal unit steps by orientation.

| Shape | First plate | Second plate |
| --- | --- | --- |
| 4 | `C[r]` | none |
| 5 | `C[r] * (dd + 1)`, default `dd` 16 | none |
| 6 | `D[r] * (dd / 2 + 1)`, default `dd / 2` 8 | none |
| 7 | `D[(r+2)&3]` | none |
| 8 | `D[r] * (dd / 2 + 1)` | `D[(r+2)&3]`, never rescaled |

Rescale (`Scene.method4502`): every nonzero axis of the first plate of the decoration already on the
tile becomes `sign * argument`. It is absolute and idempotent. It runs only when `dd != 16`, only for
a later boundary of shape 0 or 2 (argument `dd + 1`) or shape 9 (argument `dd / 2 + 1`), and only while
the scene loads. There is no separate orientation nudge inside the decoration constructor.

## Changes

| Rust before (235 rules) | Rust now (240 rules) |
| --- | --- |
| Shapes 6 and 8 used `dd / 2` | `dd / 2 + 1` |
| Shape 8 second plate at the tile centre | its own unit step along the opposite diagonal |
| Shape 7 at the tile centre | unit step along the opposite diagonal |
| Types 4 and 5 nudged one unit in `placement_requests` | the unit is part of the stock offset (shape 5 is `dd + 1`) |
| Rescale `d * dd / 16`, compounding, also for shapes 12+ | absolute `sign * (dd + 1)` or `sign * (dd / 2 + 1)`, shapes 0, 2, 9 only |
| Rescale skipped shapes 4 and 7 (zero offsets) | applies to them (nonzero unit offsets) |
| Server-added walls rescaled neighbours | load path only |
| Boundaries and decorations drawn at the footprint centre | drawn at `tile * 128 + 64`; contour and pose keep the footprint centre |
| Height corners could leave the scene | tile-corner fallback when the footprint reaches past the edge |
| `FLUSH_DIAGONAL_DECORATIONS` on | off. It was a non-stock snap compensating for the 235 offsets; it remains as an opt-in with a test |

## Not changed

- The z-bias scale (`SORT_NEAR = 50` against RuneLite's near-plane term of 100) is only suspected to
  differ by 2x; no capture measures it. Unchanged.
- Per-tile emission order (RuneLite uploads wall, decoration, ground object, game objects) is not
  matched. It only matters for exact depth ties. Unchanged.
- Per-face alpha depth sort and per-tile game-object capacity remain not ported.

## Evidence and comparison with TSPS

TSPS (`tsps-main`) is 235-style for decorations: no `+1`, no second-plate offset, an unused
multiplicative rescale, plus `wallDecorationNudge` and `embeddedWallDecorationShift` corrections that
no deob has. It was used as a negative reference only. A pixel comparison with a live reference client
was not made.

SPEC-0021 "Input arbitration" is accepted and implemented in this change: `game-ui::arbitration`
